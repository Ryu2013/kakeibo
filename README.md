# 家計簿アプリ セットアップ手順

スプレッドシートをデータベースに、GitHub Pagesをフロントにした割り勘家計簿アプリ。

## 1. スプレッドシート + Apps Script の準備

1. Google Sheets で新しいスプレッドシートを作成する
2. メニューの「拡張機能」→「Apps Script」を開く
3. デフォルトの `Code.gs` の中身を全部消して、このリポジトリの `gas/Code.gs` の内容を貼り付ける
4. 保存する（Ctrl+S）
5. 右上の「デプロイ」→「新しいデプロイ」をクリック
6. 種類の選択で「ウェブアプリ」を選ぶ
7. 設定:
   - 実行するユーザー: **自分**
   - アクセスできるユーザー: **全員**
8. 「デプロイ」をクリックし、承認を求められたら自分のGoogleアカウントで許可する
9. 発行された **ウェブアプリのURL** をコピーする（`https://script.google.com/macros/s/xxxx/exec` の形）

初回実行時にシートが自動で作られます（シート名: `支出`、列: `id, 日付, 内容, 金額, 支払者, 精算済み, 全額請求`）。

### 列構成を変更したとき (2026/09 更新)

- 精算の仕組みを「精算レコードを作る」方式から「月ごとに精算済みフラグを立てる」方式に変更（`種別`列を廃止し `精算済み`列を追加）
- 1レコードごとに「割り勘 / 全額請求」を選べるように `全額請求` 列を追加

既に `支出` シートに古い形式のテストデータが入っている場合は、シートの中身を一旦全部消してから使うこと（ヘッダー行は次回のアクセス時に自動では直らないので、手動で `id, 日付, 内容, 金額, 支払者, 精算済み, 全額請求` に書き換えるか、シート自体を削除して再作成する）。

### Code.gs を変更したとき

`gas/Code.gs` を書き換えた後は、Apps Scriptエディタで保存するだけでは反映されない。
「デプロイ」→「デプロイを管理」→ 既存デプロイの鉛筆アイコン →
バージョンを「新バージョン」にして「デプロイ」を押すまでが必須。

### 合言葉の変更

`gas/Code.gs` 内の `PASSPHRASE` を書き換えて、上記の手順で新バージョンとしてデプロイし直せば変更できる。

### 古い記録の自動削除（月次バッチ）

18ヶ月（1年半）より前の**精算済み**記録を毎月自動で削除する。未精算のまま古くなった記録は誤削除を避けるため残る。

設定は一度だけでよい:

1. Apps Scriptエディタ上部の関数選択ドロップダウンで `installMonthlyCleanupTrigger` を選ぶ
2. ▶（実行）を押す。初回は権限の確認を求められるので許可する
3. 左サイドバーの時計アイコン（トリガー）に、`cleanupOldRecords` が「月タイマー」で登録されていれば設定完了

保持期間を変えたい場合は `gas/Code.gs` の `RETENTION_MONTHS` を書き換えてデプロイし直す（トリガー自体の再設定は不要）。

## 2. フロント（index.html）の設定

`index.html` 内の以下の行を、手順1でコピーしたURLに書き換える。

```js
const GAS_URL = 'PUT_YOUR_GAS_WEBAPP_URL_HERE';
```

このURLはクライアント側のJSにそのまま埋め込まれるため、GitHub Pagesで公開すると誰でもソースから見える。
アクセス制限は合言葉のみで担保しているので、それ以上の秘密情報とは思わないこと。

## 3. GitHub Pages で公開

1. このフォルダの内容でGitHubリポジトリを作成し、push する
2. リポジトリの Settings → Pages → Source を「main ブランチ / (root)」に設定
3. 発行されたURL（`https://<user>.github.io/<repo>/`）にアクセス

## 使い方

- アプリを開くとまずログイン画面が表示され、**ログインID（aoi=碧 / ryu=竜）と合言葉**の入力が必須（閲覧・追加・削除・精算すべてに必要）
- ログインIDによって「支払者」が自動的に決まるので、記録のたびに碧/竜を選ぶ必要はない。別の人としてログインし直したいときは画面上部の「切替」から
- 一度ログインすればブラウザに保存され、以後は自動でログインされる
- 画面最上部の年月ハンドル（矢印 or 左右スワイプ）で月を切り替えると、残高表示と記録一覧が両方その月のものに連動する
- 残高は「表示中の月の、未精算の記録だけを合計した金額」
- 「＋ 記録を追加」を押すと新規登録ダイアログが開く。ダイアログ内で日付・金額・内容・支払者（デフォルトはログイン中の人だが変更可）・「割り勘 / 全額請求」を入力して「追加」すると、通信せず未送信リストにその場で積まれる。まとまったらダイアログ内の「送信する」で1回の通信でまとめて送信する（フォームで都度通信して待たされるのを避けるため）
- 「全額請求」を選ぶとそのレコードは折半せず全額がそのまま残高に計上される。デフォルトは「割り勘」
- 記録一覧の行をタップすると編集ダイアログが開き、日付・金額・内容・支払者・割り勘/全額請求を修正できる（「更新する」）ほか、「削除する」もここから行う
- 表示中の月の記録がすべて未精算のとき「この月を精算済みにする」ボタンが出る。押すと確認ダイアログの後、その月の全記録に精算済みフラグが立ち、以後は残高計算から除外される
- 削除・更新・精算・送信など通信を伴う操作の間は画面全体がロードアニメーションで覆われ、二重操作を防ぐ。通信自体が失敗した場合はトーストでエラーが表示される（未送信リストの中身は消えないので送信し直せる）

## グラフページ

左上のハンバーガーメニュー →「家計簿グラフ」で`graph.html`に遷移し、月ごとに二人が使った金額の合計（割り勘・全額請求の区別なく、単純な支出合計）を棒グラフで確認できる。誰がいくら借りているかではなく「二人でいくら使ったか」を見るためのグラフ。ログイン済みであれば追加のログインは不要（`index.html`と同じ合言葉をブラウザから読む）。グラフ画面にも同じハンバーガーメニューがあり、「家計簿」で記録画面に戻れる。グラフ描画には [Chart.js](https://www.chartjs.org/) をCDN経由で利用している。

## 買い物リスト

左上のハンバーガーメニュー →「買い物リスト」で`shopping.html`に遷移する。「＋ 買うものを追加」から新規登録ダイアログを開き、追加はその場では通信せず未送信リストに積むだけ。まとまったらダイアログ内の「送信する」で1回の通信でまとめて送信する（家計簿アプリの記録追加と同じ考え方）。チェックを入れると購入済みとして扱われ、チェックはタップ即座に見た目が変わる楽観的更新（通信は裏で行う）。項目のテキスト部分をタップすると編集ダイアログが開き、内容の変更・削除ができる。

買い物リストはレコード数が増えやすい想定なので、**購入済みになってから7日経過した項目は自動で削除**される（未購入の項目は件数が増えても消えない）。設定は一度だけでよい:

1. Apps Scriptエディタ上部の関数選択ドロップダウンで `installDailyShoppingCleanupTrigger` を選ぶ
2. ▶（実行）を押す（初回のみ権限確認）
3. トリガー一覧に `cleanupOldShoppingItems` が「日タイマー」で登録されていれば設定完了

保持日数を変えたい場合は `gas/Code.gs` の `SHOPPING_RETENTION_DAYS` を書き換えてデプロイし直す（トリガーの再設定は不要）。

初回アクセス時にスプレッドシートへ`買い物`シートが自動で作られる（列: `id, 内容, 購入済み, 購入日時`）。

## やることリスト

左上のハンバーガーメニュー →「やることリスト」で`todo.html`に遷移する。買い物リストと全く同じ作り（新規登録ダイアログでの一時保存→まとめて送信、チェックで完了、テキストタップで編集/削除ダイアログ）で、対象が「買うもの」から「やること」に変わっただけ。

こちらも**完了になってから7日経過した項目は自動で削除**される（未完了の項目は消えない）。設定は買い物リストと同様に一度だけでよい:

1. Apps Scriptエディタ上部の関数選択ドロップダウンで `installDailyTodoCleanupTrigger` を選ぶ
2. ▶（実行）を押す（初回のみ権限確認）
3. トリガー一覧に `cleanupOldTodoItems` が「日タイマー」で登録されていれば設定完了

保持日数を変えたい場合は `gas/Code.gs` の `TODO_RETENTION_DAYS` を書き換えてデプロイし直す（トリガーの再設定は不要）。

初回アクセス時にスプレッドシートへ`やること`シートが自動で作られる（列: `id, 内容, 完了, 完了日時`）。

## 同時編集について

書き込み系の操作（追加・削除・精算）はApps Script側の`LockService`で直列化しており、ほぼ同時に2人が操作しても片方が少し待たされてから処理される。競合検出や自動マージはせず、後から実行された操作の結果がそのまま残る（完全後勝ち）。

## ホーム画面に追加する（PWA）

`manifest.json` / `sw.js` / アイコン一式を同梱済みなので、ネイティブアプリっぽく起動できる。

- **iPhone (Safari)**: 共有ボタン → 「ホーム画面に追加」。専用アイコンで、アドレスバーなしのフルスクリーンで起動する
- **Android (Chrome)**: メニュー →「アプリをインストール」（自動でインストールバナーが出ることもある）

アイコンは `icon-192.png` / `icon-512.png` / `apple-touch-icon.png`。差し替えたい場合はこれらのファイルを同名のPNGで上書きすればよい。

`sw.js` はアプリ本体(index.html)を常にネットワーク優先で取得し、オフライン時だけキャッシュにフォールバックする設定にしてある。開発中に更新した内容が反映されないということは基本的に起きない。

ホーム画面に追加した状態（スタンドアロン表示）だとブラウザのリロードボタンが使えないため、各ページ右上に⟳ボタンを用意している（`location.reload()`を呼ぶだけ）。
